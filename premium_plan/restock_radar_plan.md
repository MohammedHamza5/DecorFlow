# 📡 خطة رادار النواقص والأوامر التلقائية للموردين (Smart Restock Radar Plan)

يوضح هذا المستند طريقة عمل نظام تتبع المخزون الذكي ورصد النواقص، وتوليد أوامر الشراء وإرسالها للموردين تلقائياً لتجنب نفاد المخزون وضمان انسيابية العمل بالمحل.

---

## ⚙️ منطق عمل رادار النواقص (Restock Radar Logic)

يعمل رادار النواقص على تحليل بيانات المخزون والمبيعات لتحديد السلع الحرجة وتفادي التوقف عن البيع:

1. **مراقبة مستويات المخزون (Inventory Monitoring):**
   * قراءة الكمية الحالية المتاحة (`current_stock`) لكل صنف في جدول المخزن.
   * قراءة "الحد الأدنى للأمان" (`safety_stock_level`) المسجل للصنف.
2. **الحساب الديناميكي لحد الأمان (Dynamic Safety Stock Level):**
   * لحساب حد الأمان تلقائياً في حال عدم إدخاله يدوياً:
     * يقوم التطبيق بحساب متوسط استهلاك الصنف اليومي (Daily Sales Velocity - $V$) بناءً على فواتير المبيعات الصادرة في آخر 30 يوماً.
     * حد الأمان الديناميكي = $V \times \text{فترة التوريد المتوقعة باليوم } (L)$.
     * (مثال: إذا كان المحل يبيع متوسط 5 أعواد بديل خشب يومياً، ويستغرق المورد 3 أيام لإيصال الطلبية الجديدة، فإن حد الأمان الآلي هو $5 \times 3 = 15$ عوداً).
3. **التصنيف الثلاثي لحالة المخزون:**
   * **آمن (Safe):** الكمية الحالية أكبر من حد الأمان بـ 20% فأكثر.
   * **منخفض (Low Stock):** الكمية الحالية تقترب من حد الأمان (بين 100% و 120% من حد الأمان).
   * **حرج (Critical):** الكمية الحالية أقل من حد الأمان (تحتاج لإعادة طلب فورية).

## 💾 جداول الموردين والنواقص (Supabase Schema additions)

لتكامل رادار النواقص برمجياً، سنقوم بإضافة جداول لدعم أتمتة الطلبيات:

```sql
-- 1. ربط المنتجات بالموردين الرئيسيين
CREATE TABLE IF NOT EXISTS public.premium_supplier_contacts (
    id uuid DEFAULT gen_random_uuid() PRIMARY KEY,
    shop_id uuid NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
    name text NOT NULL, -- اسم الشركة أو المورد (مثال: شركة الفتح لدمج البلاستيك)
    contact_person text, -- اسم الشخص المسؤول
    phone text NOT NULL, -- رقم الهاتف لإرسال طلبات الـ WhatsApp
    email text,
    category_supplied text, -- نوع المواد التي يوردها (بديل رخام، إكسسوارات...)
    is_active boolean DEFAULT true,
    created_at timestamp with time zone DEFAULT now()
);

-- 2. حقول إضافية لجدول المنتجات/المخزن الحالي (يتم دمجها أو الحفاظ عليها بجدول ملحق)
CREATE TABLE IF NOT EXISTS public.premium_inventory_radar (
    product_variant_id uuid PRIMARY KEY REFERENCES public.product_variants(id) ON DELETE CASCADE,
    supplier_id uuid REFERENCES public.premium_supplier_contacts(id) ON DELETE SET NULL,
    safety_stock_override numeric, -- حد أمان مدخل يدوياً (اختياري)
    restock_order_quantity numeric DEFAULT 50 -- الكمية المعتادة للطلب عند إعادة الشحن
);
```

## 📱 واجهات الاستخدام (UI Screens)

1. **لوحة تحكم رادار النواقص (Restock Radar Dashboard):**
   * بطاقات إحصائية للمواد الحرجة والمنخفضة.
   * قائمة بالمواد التي تقع تحت خط الأمان مع تلوين حالة المنتج (أصفر للنواقص الطفيفة، وأحمر للنواقص الحرجة).
   * فلترة حسب المورد أو حسب فئة المنتجات.
   * خيار لتحديد المواد المراد طلبها وتجميعها في سلة إعادة طلب موحدة للمورد.

2. **شاشة تفاصيل الطلبية وتوليد المستند (Purchase Order Generator):**
   * عرض كود المنتج، الاسم، والمخزون الحالي، والكمية المقترحة لإعادة الطلب لتغطية معدل المبيعات.
   * خيار تعديل الكميات المقترحة يدوياً قبل الإرسال.
   * زر **"مشاركة أمر الشراء عبر WhatsApp 💬"**:
     * توليد نص منسق وجاهز لإرساله لدردشة المورد مباشرة بضغطة زر.
     * صيغة الرسالة:
       > *"مرحباً [اسم المسؤول في شركة المورد]،*
       > *نود من [اسم المحل الخاص بك] طلب المواد التالية كأمر شراء مستعجل:*
       > *1. بديل رخام موديل VR-102 - الكمية: 20 لوح.*
       > *2. سيليكون تركي شفاف - الكمية: 5 كرتونة.*
       > *يرجى تأكيد استلام الطلب وإفادتنا بالموعد المتوقع للتسليم وقيمة الفاتورة.*
       > *شاكرين لتعاونكم الطيب."*
   * زر لتصدير أمر الشراء كملف PDF رسمي يحمل شعار وتفاصيل المحل لحفظه أو طباعته للتوثيق.
